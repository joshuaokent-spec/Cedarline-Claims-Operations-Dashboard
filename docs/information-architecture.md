# Information Architecture & Task Model

## Global navigation

- My Work
- Claims
- Calendar
- Documents
- Reports

The prototype begins with **My Work**, because the flagship internal question is action prioritization.

## My Work page

### Workload summary

- Needs action today
- Overdue
- Contact gaps
- Missing documents

These are entry points into filtered work, not vanity metrics.

### Queue controls

- Search by claimant or claim number
- Priority
- Claim stage
- Line of business
- Operational flag
- Sort order

### Claims work queue

Core columns:

- Claim / claimant
- Loss
- Stage
- Next action
- Due
- Last contact
- Signals

### Claim detail workspace

When a claim is selected:

- identity + status;
- claimant/contact context;
- next action;
- operational flags;
- financial snapshot;
- missing documents;
- timeline / recent activity;
- direct task actions.

## Task model

**Scan queue → identify reason for attention → open file → review context → perform or schedule next action → update state → return to queue**

The queue and file workspace must support this loop repeatedly without unnecessary navigation.
